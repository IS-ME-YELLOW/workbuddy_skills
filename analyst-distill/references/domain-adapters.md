# 领域适配器（Domain Adapters）

> **定位**：回答"面对一个新领域/新类型分析师，框架怎么落地"。已有类型给翻译要点；未知类型给自适应路径；任何平台给降级方案。
> **原则**：验收清单（acceptance-checklist.md）是**唯一强制标准**，本文件全部内容均为**参考经验**。本文件只沉淀跨案例稳定的类型模式，不记录单个分析师的孤立经验，也不随每次蒸馏自动扩写。

---

## 零、类型模式晋升门槛

默认处理路径是：完成分析师独立 skill → 交付产物；只有在用户要求或案例具有示范价值时，才归档到 `examples/`。`domain-adapters.md` 的更新门槛更高，必须满足以下条件后才写入：

- **跨案例稳定**：同一领域/类型至少有 2 个以上案例反复出现相似的框架分层、信号形态、数据侧重或验证陷阱；若只有 1 个案例，只能写成"待验证假设"，不得升格为通用适配器
- **可迁移**：新增内容能指导后续分析师蒸馏，而不是只解释某一位分析师为什么特殊
- **不与验收清单重复**：结构完整性、来源标注、观点/规则分离等通用标准只放在 `acceptance-checklist.md`，不在本文件复述
- **不写硬阈值**：阈值、权重、参数属于具体分析师；本文件只写"信号形态/常见数据族/落地注意"
- **有明确证据来源**：写明来自哪些 examples 或验证报告；无法指出来源时，不进入本文件
- **用户确认**：新增或改写已有类型模式前，先向用户说明"为什么值得晋升"，经确认后再更新

推荐写法：`类型名 → 适用对象 → 框架分层倾向 → 信号形态 → 数据侧重 → 常见落地难点 → 参考 examples`。避免按人名堆经验。

## 一、已有类型模式翻译要点（⚠️ 参考经验，按类型维护）

本节维护"类型模式"，不是分析师百科。分析师姓名只作为样本来源或参考 examples，不能把某个人的专属判断、阈值、观点写成领域通则。

### 宏观状态型

- **适用对象**：以经济周期、流动性、通胀、信用、景气度解释资产表现的宏观或大类配置分析师。
- **框架分层倾向**：总量状态 → 结构差异 → 择时信号 → 大类/风格配置。必须先从分析师原文提取其自己的分层词，再决定是否采用这一路径。
- **信号形态**：月度或季度状态信号为主，常见形式是方向变化、扩散强弱、分位位置、增速拐点、多个宏观变量共振。
- **数据侧重**：货币信用、价格、景气、盈利、利率、汇率、股债性价比等时间序列。
- **常见落地难点**：宏观变量发布滞后，历史口径可能修订；使用最新数据复算历史事件时必须避免前视偏差。
- **参考 examples**：`examples/macro-guolei`、`examples/macro-zhangyu`。

### 政策事件开关型

- **适用对象**：以政策优先级、地缘事件、监管变化、产业政策或重大会议作为主导变量的宏观、策略或行业分析师。
- **框架分层倾向**：约束/目标排序 → 事件状态识别 → 资产或风格映射 → 触发后的确认条件。
- **信号形态**：离散开关、互斥状态、事件打分、叙事强度变化；不要把事件开关直接等同于涨跌方向，应说明它改变的是风险偏好、风格倾斜或配置约束。
- **数据侧重**：事件时间线、政策文本、利率/汇率/商品/主题指数等可观测代理。
- **常见落地难点**：事件变量缺少结构化数据，常需人工 extras 或锚点表；必须标注为 ⚠️ 或 ❌，不得伪装成客观量化指标。
- **参考 examples**：`examples/macro-lichao`。

### 策略资产配置型

- **适用对象**：以估值、风险溢价、资金流、海外传导、市场结构和行业主线来给出仓位/风格/区域配置的策略分析师。
- **框架分层倾向**：主要矛盾或市场阶段 → 资产定价变量 → 资金与情绪 → 风格/行业/区域落地。
- **信号形态**：仓位建议、风格切换、区域比较、结构主线排序；常把估值空间与资金催化结合，而不是只看单个指标。
- **数据侧重**：ERP/PE/股息率分位、资金流、成交占比、拥挤度、海外利率汇率、盈利或财报增速。
- **常见落地难点**：同名指标的数据源口径差异很大；绝对阈值不能跨口径直接比较，优先使用分位、方向或同口径历史排序。
- **参考 examples**：`examples/strategy-zhangyidong`、`examples/strategy-liuchenming`。

### 趋势与阶段演进型

- **适用对象**：用价格趋势、牛熊阶段、主线拥挤度、资金供给或市场生态演进来判断配置节奏的策略、行业或主题分析师。
- **框架分层倾向**：阶段定义 → 阶段切换条件 → 仓位/攻守结构 → 行业或主题落地。
- **信号形态**：阶段状态机、趋势确认、拥挤度预警、主线延续/切换；阶段类判断通常需要 extras 保存人工判定。
- **数据侧重**：指数价格、均线、成交结构、主题指数、资金流、估值分位、产业链代理指标。
- **常见落地难点**：定性词如"高位""低位""拥挤""出清"必须转成可替换代理；高置信低覆盖信号不能被解释为未触发即安全。
- **参考 examples**：`examples/strategy-liuchenming`、`examples/strategy-fujingtao`。

### 固收区间锚型（待更多案例验证）

- **适用对象**：以收益率区间、期限利差、资金面、供需、机构行为和策略工具排序为核心的固收分析师。
- **框架分层倾向**：多因子状态评估 → 点位/区间锚 → 期限与品种策略 → 杠杆/久期/信用/权益暴露。
- **信号形态**：方向信号、边界信号、均值回复信号和状态信号并存；固收的"仓位"常体现为久期、杠杆、曲线和品种选择。
- **数据侧重**：收益率曲线、资金利率、存单、社融/政府债供给、名义增长、信用利差、股债性价比、机构行为代理。
- **常见落地难点**：区间锚可能随年度大幅移动，历史复算需按当期参数分段；微观持仓/久期/分歧度常缺公开源，应设计 OPTIONAL 字段与降级提示。
- **参考 examples**：`examples/fixed-income-zhangjiqiang`。该类型目前样本较少，新增内容进入本节前需满足"类型模式晋升门槛"。


## 二、新领域自适应路径（应对开放类型：金工/行业/买方/机构……）

**核心原则：不强行套已有分层，按该分析师自己的方法论主体提炼。**

> 单个首例只能证明路径可运行，不能自动证明类型模式稳定。首例经验应优先放入该案例的 `validation.md`；只有满足"类型模式晋升门槛"后，才沉淀到本文件。

1. **Phase 1 加一轮"领域特有跟踪指标体系"检索**：除标准 4 组检索主题外，必须检索"该分析师常用的指标/数据/模型工具"，作为 indicators.md 的原料（例：固收→收益率曲线/利差/久期/信用利差；金工→因子/IC/换手；买方→组合约束/风险预算/回撤控制）
2. **框架分层以分析师原话为准**：Phase 2 提取时，先列出分析师自己在研报/访谈中使用的分类词（如"自上而下/自下而上""核心+卫星"），据此定 framework.md 的分层章节，**不复制**宏观/策略的分层标题
3. **产出结构以验收清单为准**：references×3 + assets×3 + screen.py 的结构对任何类型不变（这是领域无关的部分）；变化只在内容翻译
4. **examples 只参考结构最近的**：无同类样例时读 `examples/strategy-zhangyidong`（结构最全）学"标注纪律与深度手感"，**禁止照搬领域内容/阈值/框架名**
5. **信号形态可扩展**：固收可用"曲线信号/利差信号"、金工可用"因子信号/拥挤度信号"——S 编号体系不变，信号名称随领域
6. **完成后处理**：默认不更新本文件；若用户要求或案例具备示范价值，可归档到 `examples/` 并更新索引。只有满足"类型模式晋升门槛"并经用户确认后，才把跨案例稳定经验写入本文件

## 三、平台降级方案（目标：任何平台都能跑）

| 能力 | WorkBuddy（完整版） | 降级做法（无对应工具时） |
|---|---|---|
| 金融数据 | westock-data / westock-tool / neodata 直连 | Phase 4 数据缺口按 ⚠️观点锚点/❌工程代理 标注，注明"数据源不可用"；验证结论只做方向性判断 |
| 技能校验 | package_skill.py（"Skill is valid"） | 按 acceptance-checklist.md §1/§9 人工逐条勾选替代机器校验 |
| skill 安装 | 写入 `~/.workbuddy/skills/` + zip 打包 | 产物以"目录 + zip"交付，由用户自行安装/导入 |
| 汇报通道 | 对话内图文 + present_files | 同（对话即交付通道） |

**平台无关核心**（任何平台都自包含）：五阶段流程（SKILL.md）+ 验收清单（acceptance-checklist.md）+ 脚本规范与骨架（scripts-conventions.md + screen_template.py）+ 示范样本（examples/）。**数据源与打包工具是增强项，不是必需品。**

## 四、跨领域冲突处理

- 同一分析师横跨多领域（如宏观+策略）：按其主要市场角色定 specialty，另一面写进 profile.md 差异化节
- 新领域与已有领域结论冲突：不调和、不覆盖，如实记录双方口径差异（validation.md 口径差异节）
- 领域特有红线（如机构合规、买方保密）：在成品 SKILL.md 红线节单独列出，不进通用模板
